## 1. 프로젝트 관리

### 1.1 프로젝트 선택
**As a** 사용자
**I want to** 로컬 파일 시스템에서 프로젝트 디렉토리를 선택할 수 있다
**So that** 선택한 프로젝트에 워크플로우를 저장하고 관리할 수 있다

#### 상세 기능
- 디렉토리 브라우저를 통한 시각적 탐색
  - 홈 디렉토리에서 시작
  - 상위 디렉토리 이동
  - 하위 디렉토리 더블 클릭으로 진입
- 텍스트 입력으로 경로 직접 입력
- 선택한 프로젝트 경로 표시 및 localStorage 저장
- 앱 재시작 시 마지막 선택 프로젝트 자동 로드

#### 수락 조건
- [ ] 브라우저와 텍스트 입력 방식을 전환할 수 있다
- [ ] 권한이 없는 디렉토리는 선택 불가능하다
- [ ] 현재 선택된 프로젝트가 헤더에 표시된다

---

### 1.2 프로젝트 데이터 관리
**As a** 사용자
**I want to** 프로젝트의 세션, 로그, 노드 세션을 관리할 수 있다
**So that** 불필요한 데이터를 정리하고 디스크 공간을 확보할 수 있다

#### 상세 기능
- 프로젝트 설정 메뉴 (헤더의 톱니바퀴 버튼)
  - **로그 & 세션 보기**: 저장된 모든 로그와 세션 파일 탐색
  - **모든 노드 세션 초기화**: 각 노드의 대화 기록 삭제
  - **프로젝트 세션 비우기**: 워크플로우 실행 세션 삭제
  - **로그 비우기**: 모든 로그 파일 삭제
- 삭제 시 확인 다이얼로그 표시
- 삭제 후 확보된 용량 표시

#### 수락 조건
- [ ] 각 작업에 대한 확인 다이얼로그가 표시된다
- [ ] 삭제 후 피드백(삭제된 파일 개수, 확보된 용량)이 표시된다
- [ ] 실행 취소는 불가능하다는 경고가 표시된다

## 2. 워크플로우 설계

### 2.1 워크플로우 생성 및 편집
**As a** 사용자
**I want to** 비주얼 캔버스에서 노드를 배치하고 연결하여 워크플로우를 설계할 수 있다
**So that** AI 에이전트들의 작업 흐름을 시각적으로 구성할 수 있다

#### 상세 기능
- 드래그 앤 드롭으로 노드 추가
  - 왼쪽 패널에서 노드 드래그
  - 또는 클릭하여 자동 배치
- 노드 간 연결
  - 노드의 핸들을 드래그하여 연결
  - 화살표 애니메이션으로 방향 표시
- 캔버스 조작
  - 팬(드래그 이동)
  - 줌(확대/축소)
  - 미니맵으로 전체 구조 확인
- 그리드 스냅 기능 (16px 단위)

#### 수락 조건
- [ ] 노드를 드래그하여 원하는 위치에 배치할 수 있다
- [ ] 노드를 연결하면 애니메이션이 표시된다
- [ ] 미니맵에서 전체 워크플로우를 한눈에 볼 수 있다

---

### 2.2 워크플로우 자동 설계
**As a** 사용자
**I want to** 요구사항을 입력하면 AI가 자동으로 워크플로우를 설계해준다
**So that** 복잡한 워크플로우를 직접 구성하지 않아도 된다

#### 상세 기능
- "워크플로우 자동 설계" 버튼 클릭
- 요구사항을 자연어로 입력
- AI가 실시간으로 워크플로우 설계
  - 적절한 노드 선택
  - 노드 간 연결 구성
  - 각 노드의 프롬프트 자동 생성
- 설계 진행 상황 실시간 표시
- 완료 후 캔버스에 자동 적용

#### 수락 조건
- [ ] 요구사항을 입력하면 워크플로우가 자동 생성된다
- [ ] 생성 중 진행 상황을 확인할 수 있다
- [ ] 새로고침 시 진행 중인 세션이 자동 복구된다

---

### 2.3 워크플로우 저장 및 불러오기
**As a** 사용자
**I want to** 작성한 워크플로우를 저장하고 나중에 불러올 수 있다
**So that** 작업 내용을 보존하고 재사용할 수 있다

#### 상세 기능
- **자동 저장** (5초 debounce)
  - 노드/엣지 변경 시 자동 저장
  - 저장 상태 실시간 표시 (대기 중/저장 중/저장됨)
  - 실행 중에는 자동 저장 비활성화
- **수동 저장** (Cmd/Ctrl + S)
  - 헤더의 "저장" 버튼 또는 단축키
  - 실행 중에는 저장 불가
- **워크플로우 선택**
  - 드롭다운에서 저장된 워크플로우 선택
  - 새 워크플로우 생성
- 워크플로우 이름 편집 (헤더의 입력 필드)

#### 수락 조건
- [ ] 노드를 변경하면 5초 후 자동 저장된다
- [ ] Cmd+S로 즉시 저장할 수 있다
- [ ] 저장 상태가 헤더에 표시된다
- [ ] 워크플로우 실행 중에는 저장할 수 없다

---

### 2.4 템플릿 갤러리
**As a** 사용자
**I want to** 사전 정의된 워크플로우 템플릿을 선택하거나 가져올 수 있다
**So that** 일반적인 작업에 대한 워크플로우를 빠르게 시작할 수 있다

#### 상세 기능
- **템플릿 갤러리** 모달 (헤더의 "템플릿" 버튼)
  - 카테고리별 필터링
  - 검색 기능
  - 템플릿 미리보기 (노드 개수, 연결 개수, 설명, 태그)
- **내장 템플릿**: 삭제 불가
- **커스텀 템플릿**: 생성 및 삭제 가능
- **워크플로우 가져오기**: JSON 파일 업로드
- **워크플로우 내보내기**: JSON 파일 다운로드

#### 수락 조건
- [ ] 카테고리와 검색으로 템플릿을 필터링할 수 있다
- [ ] 템플릿을 선택하면 현재 워크플로우가 대체된다
- [ ] JSON 파일로 워크플로우를 가져오고 내보낼 수 있다

---

## 3. 노드 구성

### 3.1 Input 노드
**As a** 사용자
**I want to** 워크플로우의 시작점을 설정할 수 있다
**So that** 초기 입력 데이터를 제공하고 워크플로우를 시작할 수 있다

#### 상세 기능
- 워크플로우 시작점 역할
- 초기 입력 텍스트 설정
- 템플릿 문법 지원 (`{{variable}}`)
- 실행 시 입력 필드로 동적 입력 가능

#### 수락 조건
- [ ] Input 노드에서 워크플로우를 시작할 수 있다
- [ ] 실행 시 입력 값을 동적으로 변경할 수 있다
- [ ] 여러 Output 노드로 연결 가능하다

---

### 3.2 Worker 노드
**As a** 사용자
**I want to** 다양한 AI 에이전트(워커)를 활용하여 작업을 수행할 수 있다
**So that** 계획, 코딩, 리뷰, 테스트 등의 작업을 자동화할 수 있다

#### 상세 기능
- **범용 워커** (9개)
  - planner, coder, reviewer, tester, committer
  - ideator, product_manager, documenter, local
- **특화 워커** (22개)
  - 계획: feature_planner, refactoring_planner, bug_fix_planner, api_planner, database_planner
  - 코드: frontend_coder, backend_coder, test_coder, infrastructure_coder, database_coder
  - 리뷰: style_reviewer, security_reviewer, architecture_reviewer
  - 테스트: unit_tester, integration_tester, e2e_tester, performance_tester
  - 기타: bug_fixer, log_analyzer, summarizer
- **커스텀 워커**: 사용자가 직접 생성
- 각 워커는 고유한 시스템 프롬프트 보유
- 작업 템플릿 설정 (`{{parent}}` 문법으로 이전 노드 출력 참조)
- 허용 도구 설정 (Read, Write, Edit, Bash, etc.)
- 모델 선택 (opus, sonnet, haiku)
- 사고 과정(thinking) 활성화 여부 설정

#### 수락 조건
- [ ] 범용/특화 워커를 드래그하여 추가할 수 있다
- [ ] 각 워커의 프롬프트와 설정을 편집할 수 있다
- [ ] `{{parent}}` 문법으로 이전 노드의 출력을 받을 수 있다

---

### 3.3 커스텀 워커 생성
**As a** 사용자
**I want to** 나만의 특화된 워커를 AI의 도움을 받아 생성할 수 있다
**So that** 프로젝트 특화 작업을 자동화할 수 있다

#### 상세 기능
- "새 워커 생성" 버튼 클릭
- 워커 요구사항을 자연어로 입력
- AI가 자동으로 프롬프트 생성
  - 워커 이름 및 역할 제안
  - 시스템 프롬프트 작성
  - 필요한 도구 선택
  - 모델 추천
- 생성된 프롬프트 확인 및 편집
- 프로젝트 `.claude-flow/workers/` 폴더에 저장
- 새로고침 시 세션 자동 복구

#### 수락 조건
- [ ] 요구사항을 입력하면 워커가 자동 생성된다
- [ ] 생성된 프롬프트를 확인하고 수정할 수 있다
- [ ] 생성 중 진행 상황을 실시간으로 확인할 수 있다

---

### 3.4 Condition 노드 (조건 분기)
**As a** 사용자
**I want to** 이전 노드의 출력에 따라 다른 경로로 분기할 수 있다
**So that** 조건부 로직을 구현할 수 있다

#### 상세 기능
- 조건 타입 선택
  - `contains`: 특정 문자열 포함 여부
  - `not_contains`: 특정 문자열 미포함 여부
  - `equals`: 정확히 일치
  - `regex`: 정규 표현식 매칭
- True/False 두 개의 출력 핸들
- 조건 값 설정

#### 수락 조건
- [ ] 조건에 따라 True 또는 False 경로로 분기한다
- [ ] 4가지 조건 타입을 지원한다
- [ ] 정규 표현식으로 복잡한 조건을 표현할 수 있다

---

### 3.5 Merge 노드 (병합)
**As a** 사용자
**I want to** 여러 분기의 결과를 하나로 통합할 수 있다
**So that** 병렬 작업의 결과를 종합할 수 있다

#### 상세 기능
- 병합 전략 선택
  - `concatenate`: 텍스트 연결
  - `choose_first`: 첫 번째 입력만 사용
- 구분자 설정 (concatenate 전략 사용 시)
- 여러 입력 소스 연결 가능

#### 수락 조건
- [ ] 여러 노드의 출력을 하나로 병합할 수 있다
- [ ] 2가지 병합 전략을 지원한다
- [ ] 구분자를 커스터마이징할 수 있다

---

## 4. 워크플로우 실행

### 4.1 워크플로우 실행
**As a** 사용자
**I want to** 구성한 워크플로우를 실행하여 결과를 얻을 수 있다
**So that** AI 에이전트들이 자동으로 작업을 수행하도록 할 수 있다

#### 상세 기능
- 실행 버튼 (우측 사이드바 상단)
- Input 노드부터 시작
- 노드별 순차 실행 (토폴로지 정렬)
- 실시간 진행 상황 표시
  - 현재 실행 중인 노드 강조 (노란색 테두리)
  - 완료된 노드 표시 (초록색 체크)
  - 에러 발생 노드 표시 (빨간색 경고)
- 스트리밍 출력 (실시간 텍스트 생성)
- 세션 ID 저장 (재시작 시 복구용)

#### 수락 조건
- [ ] 워크플로우를 실행하면 노드가 순차적으로 실행된다
- [ ] 현재 실행 중인 노드를 시각적으로 확인할 수 있다
- [ ] 각 노드의 출력을 실시간으로 볼 수 있다

---

### 4.2 워크플로우 중지
**As a** 사용자
**I want to** 실행 중인 워크플로우를 중지할 수 있다
**So that** 잘못된 실행을 취소하거나 변경사항을 적용할 수 있다

#### 상세 기능
- 중지 버튼 (실행 중에만 표시)
- 현재 실행 중인 노드 중단
- 진행 상황 보존
- 세션 종료

#### 수락 조건
- [ ] 중지 버튼을 클릭하면 즉시 실행이 중단된다
- [ ] 이미 완료된 노드의 결과는 보존된다
- [ ] 세션 ID가 제거된다

---

### 4.3 실시간 워크플로우 검증
**As a** 사용자
**I want to** 워크플로우를 실행하기 전에 오류를 미리 확인할 수 있다
**So that** 실행 전에 문제를 수정할 수 있다

#### 상세 기능
- 실시간 검증 (1초 debounce)
- 검증 에러 유형
  - **순환 참조**: 무한 루프 방지
  - **고립된 노드**: 연결되지 않은 노드
  - **불완전한 입력**: 필수 설정 누락
  - **잘못된 연결**: 호환되지 않는 노드 연결
- 노드에 경고/에러 아이콘 표시
- 우측 사이드바에 검증 결과 표시

#### 수락 조건
- [ ] 노드를 변경하면 1초 후 자동 검증된다
- [ ] 검증 에러가 있는 노드에 아이콘이 표시된다
- [ ] 우측 사이드바에서 에러 상세를 확인할 수 있다

---

### 4.4 Human-in-the-Loop (사용자 개입)
**As a** 사용자
**I want to** AI가 질문을 할 때 답변을 제공할 수 있다
**So that** 워크플로우 중간에 판단이 필요한 상황에 개입할 수 있다

#### 상세 기능
- Worker가 `ask_user()` 함수 호출 시 모달 표시
- 질문 내용 표시
- 답변 입력 필드
- 제출/취소 버튼
- 답변 제출 시 워크플로우 계속 진행
